## Исправленные случаи

- Web UI проверяется по штатному пути и содержимому HTML, а не только HTTP 200.
  Посторонние страницы и Login дают FAIL, даже если API доступен. Для NN/DN
  дополнительно проверяется JMX-идентичность; для SNN/YARN используются их
  отдельные JMX/REST проверки.
- Доступность SecondaryNameNode и checkpoint разделены. `LastCheckpointDeltaMs=-1`
  даёт необязательный NOT TESTED и не блокирует smoke. Отсутствующая метрика даёт
  обычный NOT TESTED; просроченный или некорректный возраст — FAIL.
- `Pending deletion blocks > 0` выводится как INFO. Missing/corrupt/low-redundancy
  blocks по-прежнему не допускаются.
- Нестандартный SSH-ключ передаётся через `--identity-file` отдельным аргументом
  `ssh -i`, включая пути с пробелами. Файл проверяется до подключения; содержимое
  скрипт не читает. Включается `IdentitiesOnly=yes`.

Коды QA: 0 — все обязательные проверки прошли, 1 — FAIL, 2 — обязательные проверки
NOT TESTED/ошибка аргументов, 130 — прерывание. Необязательные наблюдения показаны
отдельно (`optional_not_tested`) и не меняют код. Команды имеют таймауты; smoke
по умолчанию отключён. Очистка только собственного UUID-пути, без рекурсивного
удаления; при неподтверждённом создании каталога ничего не удаляется.

## Финальная проверка на стенде

1. Укажите фактические URL и согласованный список NodeManager в копии
   `shared/qa/cluster.example.json`; задайте `jobhistory_required` по составу
   сервисов команды. Пример конфигурации сам по себе не подтверждает топологию.
2. На узле с Hadoop CLI и клиентской конфигурацией запустите команды из
   [HW1 QA](../../hw01-hdfs/QA.md) и [YARN QA](../../hw02-yarn/QA-NETWORK.md).
   Сохраните stdout/stderr и exit codes. С `tee` используйте `set -o pipefail`.
3. После разрешения на запись выполните HDFS `--smoke` в существующем личном
   каталоге. Первый ещё не выполненный checkpoint не мешает этому тесту;
   подтверждение штатного checkpoint можно получить повторной диагностикой позже.
4. На ноутбуке запустите туннели со своим ключом и откройте каждый localhost UI.
   Отдельные ссылки внутри страниц могут вести на внутренние имена: используйте
   локальный URL нужного демона. Проверка отсутствия критических ошибок в логах
   описана в HW1 QA; логи здесь не проверялись.

Ограничения профиля: штатные HTTP/HTTPS UI Hadoop 3.4, DNS/IPv4, без HTTP/SPNEGO
аутентификации, IPv6 и полного HA-профиля. TLS-проверка не отключается. На реальном
стенде ещё нужно подтвердить совместимость вывода/страниц и доступность портов.

Для независимого ревью передайте все новые файлы: обычный `git diff` не включает
untracked-файлы. Commit, push, merge/rebase и создание PR не выполнялись.
