### Точечные исправления и тесты

Первый реальный QA вернул FAIL из-за двух ограничений прежней версии QA:
обязательного дополнительного Flow tag и неучтённой строки-разделителя
`TAB NULL TAB NULL` в Hive 4 DESCRIBE. После исправления разборщика и добавления
явной проверки существующих submit-свидетельств повторный QA получил PASS.
В HTTP transport сохранены query parameters для фильтра RM.

Локально: **21/21 тест PASS**, включая прежние 18 и новые положительные/отрицательные
сценарии корреляции (чужой task/tag, повторы task, несколько приложений, неверный,
старый или отсутствующий лог), реальный Hive-разделитель и сохранение HTTP query.
Python compile и `git diff --check` — PASS. Повторного аудита HW1–HW4 не проводилось.
Используемые общие модули не менялись; их 31+16 тестов уже проходили ранее.

Подтверждены необходимые требования цепочки HW5: Prefect → Spark/YARN → HDFS
→ преобразования → конечная Hive-таблица, автоматизированная проверка и инструкция.
Остаточных блокеров данного E2E нет. UI через отдельный локальный SSH-туннель
в этом сеансе отдельно не проверялся: QA обращался к API с edge по SSH.
Сервисы не переустанавливались, чужой код не менялся, Spark повторно не запускался;
выполнялись только чтение и запись собственных QA-файлов/отчётов.

## Реальная сеть и кластер

Сначала SSH с системным конфигом завершился локальной ошибкой:

```text
Bad owner or permissions on /etc/ssh/ssh_config.d/20-systemd-ssh-proxy.conf
```

ключом и строгой проверкой host key, включая повтор вне sandbox и заключительную
попытку после реализации:

```text
Connection timed out during banner exchange
Connection to 178.236.27.186 port 22 timed out
```

SSH exit **255**. Ключ присутствует локально, его содержимое не читалось и не
выводилось. Успешная аутентификация, hostname, версии, процессы и настройки
edge не получены. Нельзя утверждать ни работоспособность, ни неисправность
внутренних сервисов по одному SSH timeout.
